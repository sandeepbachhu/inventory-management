Factory Inventory Management System

System architecture, technology stack, and data flow

Demo application. The frontend is a Vue 3 single-page app that talks to a FastAPI backend over HTTP. All data is read from JSON files and held in memory. There is no database and no authentication.

3. Frontend structure

Entry

main.js

Creates the Vue app, registers the router, and maps seven routes to views. App.vue provides the shell with navigation, the filter bar, and profile and task modals.

Views

client/src/views

Dashboard, Inventory, Orders, Demand, Spending, Reports, and Backlog. Each view loads its data through api.js and derives its display in computed properties.

API client

api.js

A single object with one method per endpoint. It builds query strings and skips any filter whose value is all.

State

composables

useFilters holds shared filter state as module-level refs, so every view sees the same filters. useAuth provides a mock user. useI18n handles the locale and stores it in localStorage.

Components

client/src/components

FilterBar, ProfileMenu, LanguageSwitcher, and TasksModal, plus detail modals for products, inventory, backlog, and cost.

The backend is a single main.py file that defines the routes, the Pydantic models, and the filter helpers. mock_data.py loads the JSON datasets once, at import time.

5. Data flow

This is the path a filtered page takes, using the Dashboard as the example.

  1. User changes a filter The FilterBar updates the shared refs in useFilters: period, warehouse, category, and status.
  2. View reads the filters getCurrentFilters() returns an object. A period becomes a month value. A watcher on the view re-runs its data load when the object changes.
  3. API client builds the request api.js adds each filter as a query parameter, skipping any value equal to all, and calls the endpoint with axios.
  4. FastAPI applies the filters apply_filters matches warehouse, category, and status. filter_by_month handles a single month (for example 2025-09) or a quarter (for example Q3-2025) by matching order_date.
  5. Summary is computed The dashboard summary endpoint totals stock value, counts low-stock items (quantity at or below the reorder point), counts pending orders (Processing or Backordered), and sums order value.
  6. Response is validated and returned Pydantic response models check each list endpoint's output. The summary endpoint returns a plain dictionary.
  7. View recomputes its display Raw responses are stored in refs. Charts, KPIs, and tables are derived from them through computed properties.

6. Observations from the code

These were found while reading the code. They are not fixed here.

High

Unimplemented task and purchase-order routes

api.js calls /api/tasks and /api/purchase-orders, but main.py does not define them. Both return 404. App.vue logs an error on load, and task changes fail.

High

Missing import in Dashboard

Dashboard.vue renders <PurchaseOrderModal> but does not import it, and no such file exists in components/. Vue logs a warning and renders it as an unknown element.

Medium

Reports bypass the API client

Reports.vue calls axios directly with a hard-coded URL instead of using api.js. Changing the API base URL would miss this view.

Medium

Client-side mock user and tasks

useAuth returns a fixed user with hard-coded tasks. Profile data is not server-backed, and there is no login.

Low

Open CORS policy

The backend allows all origins, methods, and headers. This is acceptable for a local demo and should be narrowed before any shared deployment.

Low

Quarter logic duplicated

Quarter ranges appear in QUARTER_MAP and again in the quarterly report handler. A change to one will not reach the other.
